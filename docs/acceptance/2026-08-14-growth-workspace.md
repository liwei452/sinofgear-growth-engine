# AI 推广获客工作台 MVP 验收记录

日期：2026-08-14

最近复验：2026-08-15

## 本次交付范围

- 以工厂老板为主要用户，首页采用“采购机会 + AI 品牌与渠道概览”双栏布局。
- 一级导航收敛为“今天、推广、客户机会、效果、我的公司”。旧管理页保留为隐藏兼容路由，不暴露在普通导航中。
- 采购机会明确区分 Target Account、Contact、Intent Signal、Inbound Lead，并展示来源、时间、意向等级与原始证据。
- 机会操作为“加入跟进、生成联系草稿、查看证据”；CRM 仅作为后续可选出口。
- 推广页提供 LinkedIn、Facebook、Instagram、TikTok 内容包。TikTok 包含 15–60 秒脚本、分镜、英文口播、中文字幕、9:16、标题、标签、CTA、UTM 与指标回填位。
- AI Visibility 展示评分组成、已知事实、未知事实和补充建议，不使用无解释的单一分数。
- 后端新增组织隔离的增长工作区 API、跟进与草稿端点，以及可替换的 Fake / 官方平台连接器边界。
- 已实现 Meta（Facebook Page、Instagram Business）、TikTok、LinkedIn Company Page 的官方发布适配器契约、账号连接状态和安全授权起点；默认配置保持关闭。
- 已补齐 fixture-tested 官方账号连接闭环：授权回调、可管理账号发现、10 分钟短期选择会话、明确账号确认与账号专属不透明凭据引用。授权完成本身不会连接账号或发布内容。
- 客户机会新增可解释评分：ICP 匹配、意向强度、信号时效、角色相关、证据覆盖和风险扣分共同组成总分，并保存评分规则版本、采集方式、证据 SHA-256 与待确认事项；“优先跟进”同时要求总分和证据覆盖达标。
- 客户机会支持“导入公开线索”：用户可保存自己有权使用的公司事实、公开 HTTPS 来源和证据摘要，导入后立即进入待核实队列并可刷新恢复。

## 安全与真实性边界

- 当前首页机会均有清晰的 `Demo / Fake` 标识，不冒充真实发现。
- “今天”首页已读取本地增长工作区 API；加入跟进和联系草稿会写入数据库，刷新后保留状态。
- “推广”页的 LinkedIn、Facebook、Instagram、TikTok 内容包均可独立审批；批准且账号状态可用后，可一次创建四渠道发布批次，逐渠道记录成功或失败，并只重试可重试的失败渠道。Demo 结果明确标识为 `Demo / Fake`；官方账号会标识为“官方连接”，且绝不回退到 Fake Connector。结构化手工发布包始终作为备用。
- 默认数据仍来自明确标记的稳定 Demo 种子，尚未接入真实许可数据源；用户可人工保存自己有权使用的公开线索，系统会逐条标记为“许可 / 用户提供来源”。五个一级页面均读取本地增长工作区。客户机会页按证据门槛和信号强度展示完整目标公司队列，可切换证据详情且各公司跟进状态相互独立；公司资料页可人工确认事实且刷新后保留状态。
- 人工导入不会访问或解析来源网页，不执行 DNS 查询，不接受 HTTP、账号密码、localhost、`.local`、私有/回环/保留 IP；相同组织内的同一来源与证据哈希幂等复用，不创建重复机会。
- 人工导入固定使用 `manual-opportunity-v1` 保守评分，总分 50、证据覆盖 10，并保留公司身份与采购范围待确认项，因此只能进入“继续观察”。
- 客户机会只为证据达到门槛的记录显示“优先跟进”，高总分但证据覆盖不足的记录仍显示“继续观察”；旧记录缺少评分明细时降级为明确提示，不使用神秘分数补全。
- 原始来源仅对安全的 HTTPS 地址提供外链；详情显示采集方式、发现时间、评分规则、证据哈希和不确定项。跟进时间线中的联系内容始终标记为“从未发送”。
- 未配置真实 OAuth、API 密钥或付费数据源；所有官方连接开关默认关闭，示例配置不包含密钥。
- 未发送邮件、私信，未调用任何社媒真实发布接口；本次仅通过注入式测试传输验证官方请求契约。
- 授权 state 只保存哈希，10 分钟过期、一次性使用，并绑定组织、操作者和平台；普通接口不返回 token、密钥或原始平台错误。
- Meta 会把 Facebook Page 与 Instagram Business 分成独立候选，并在账号确认后绑定账号专属凭据引用；LinkedIn 只保留已批准管理员组织；TikTok 未审核应用明确标记为“仅私密发布”。
- 推广页只显示账号名称、渠道和“可发布 / 仅私密发布”，即使只有一个候选账号也必须人工点击“使用此账号”。关闭选择卡不会连接账号，也不会创建发布批次。
- 未进入或修改 `C:\Users\Administrator\Documents\网站\app`。

## 本地验收路径

1. 打开“今天”，核对双栏首页、Demo 机会、证据、AI Visibility 解释与渠道卡片。
2. 对任一后端 Demo 机会执行“加入跟进”，刷新页面确认状态仍为已加入；生成联系草稿并核对 `NEVER_SENT` API 边界。
3. 打开“推广”，核对每个渠道的“已连接 / 未连接 / 需要重新授权”状态和“官方连接 / Demo Fake”标识。Fixture 回调测试会在此页显示“选择要用于发布的账号”；确认候选账号前不得建立连接，点击“暂不连接”不得产生任何发布请求。分别批准已连接渠道的内容包后点击一次发布，确认批次逐渠道记录结果；只允许重试标记为可重试的失败渠道。Demo 链接必须位于 `example.invalid`；手工发布包下载继续可用。
4. 打开“客户机会”，点击“导入公开线索”，提交一条有权使用的公开 HTTPS 来源；确认系统明确说明不会访问网页或自动联系，保存后显示“许可 / 用户提供来源”和“继续观察 · 50”，刷新后仍存在。重复提交相同来源和证据不能创建第二条信号。“查看证据”应显示六项评分组成、采集方式、规则版本、证据哈希和待确认事项。生成联系草稿后确认只保存为“从未发送”的待人工审核内容。
5. 打开“效果”，手工回填 TikTok 指标，刷新后确认播放和点击数据来自最新数据库记录；同时核对统计口径、日期和低样本提示。
6. 打开“我的公司”，核对事实来源、验证状态、更新成本和缺口提示；确认一项待确认事实，刷新后状态仍为“已确认”。

## 后续接入门槛

只有在用户另行授权后，才能填写真实平台应用配置、打开 OAuth 开关、进入真实账号授权、选择真实账号、执行首次真实发布，或接入真实许可数据源、付费服务、生产部署、DNS 和邮件配置。正式启用前还需完成平台应用审核、回调域名配置、加密 token store 与账号专属凭据绑定、权限核验和沙盒发布验收；现有账号确认和内容人工审核门禁必须保留。

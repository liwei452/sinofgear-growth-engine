# SinofGear AI 获客、推广与独立站闭环设计

日期：2026-08-14  
状态：已确认方向，等待书面规格复核  
涉及仓库：`sinofgear-growth-engine`、`../app`

## 1. 目标

把现有增长系统和独立站改造成一条可实际使用的工业外贸增长闭环：

```text
上传产品/手册
→ AI理解企业与产品
→ AI提出推广和获客方案
→ 用户批准
→ 社媒及独立站发布
→ 每日公开信号监测
→ 企业补全、证据评分和机会排序
→ 独立站访问、资料下载或询盘
→ 来源归因
→ 人工确认
→ CRM交接
→ 结果反馈给下一轮AI决策
```

成功标准不是“系统里有多少模块”，而是新手能否在不理解 Campaign、ContentBrief、Prompt、SourceSignal 和 PublishTask 的情况下完成以下三件事：

1. 上传产品资料并批准一套推广方案；
2. 查看AI每天发现的真实客户机会及依据；
3. 查看哪些推广带来了独立站访问和询盘。

## 2. 已确认业务与网站状态

- 产品不是CRM、销售管理或自动群发系统；CRM仅是确认后交接目标。
- `sinofgear-growth-engine` 是唯一运营大脑，负责企业/产品知识、AI任务、内容、获客、审核、追踪与CRM交接。
- `../app` 是唯一公开独立站，负责SEO、产品和博客展示、资料承接、询盘与转化事件。
- 正式站保持 `https://sinfogear.com`。
- `sinofgear.com` 当前为注册局 `serverHold`，迁移暂停，不能作为正式落地页。
- `sinoforce.net` 尚未完成GoDaddy账户间转移，交接前不修改DNS或canonical。
- 询盘收件地址保持 `452900431@qq.com`，发件身份保持 `inquiries@sinfogear.com`；未经单独确认不修改配置、不发送真实测试询盘。
- 独立站已有产品页、英文技术博客、五语内容、静态预渲染、SEO、sitemap、robots、询盘表单、图纸附件、Cloudflare Pages Functions、Resend通知和基础转化埋点。
- 独立站仓库当前存在用户未提交的历史文件删除记录，实施时必须保持原样并隔离开发。

## 3. 产品边界

### 3.1 纳入

- 产品手册、PDF、图片和已有资料的AI抽取；
- 人工批准的企业知识和产品事实；
- Growth Director、Content Agent、Lead Intelligence、AIEO Agent、Analytics Agent；
- 文字模型及图片生成、图片编辑等多模态Provider接口；
- 外文推广内容及完整中文对照；
- 官方API/OAuth允许范围内的社媒发布和数据读取；
- 独立站博客、案例、FAQ和产品资产发布；
- UTM、内容ID、产品ID和来源平台归因；
- 公开信号、企业信息和证据化潜客排序；
- 询盘回传与人工CRM交接。

### 3.2 不纳入

- CRM漏斗、销售绩效、报价、订单和销售团队管理；
- 保存第三方社媒账号密码、验证码或Cookie；
- 绕过验证码、反机器人措施或平台访问控制；
- 自动陌生私信、自动群发或无人审核的冷邮件；
- AI自主承诺价格、交期、精度、认证、材料或生产能力；
- 新增第三套通用营销后台、Agent OS或自动化编排平台。

## 4. 产品交互设计

### 4.1 普通用户前台

主导航只保留：

1. `今天`：AI完成了什么、哪些事项需要决定；
2. `开始推广`：上传产品或选择已有产品，输入一句可选目标；
3. `客户机会`：按价值排序的机会、证据与CRM交接；
4. `效果`：访问、询盘、产品和渠道结论；
5. `公司资料`：AI已理解的事实和必须补充的缺口。

普通用户不看到 Campaign、ContentBrief、Ontology、AIRun、PromptVersion、SourceSignal、Job、PublishTask 和 ConnectorCredential 等对象名。

### 4.2 首次使用

系统只要求：

- 上传产品手册、产品图片或选择已有产品；
- 可选输入一句目标，例如“推广到德国包装机械行业”。

AI自动读取企业资料、产品知识、历史内容、网站页面、平台能力和已有素材，生成一份方案：

- 推广产品和推荐理由；
- 优先市场与客户类型；
- 社媒平台和独立站内容；
- 7至30天发布计划；
- 潜客监测关键词、企业与同行来源；
- 预估外部API费用；
- 必须人工补充或确认的事实。

用户只选择 `批准执行`、`调整目标` 或 `暂不执行`。所有可推断参数默认折叠在“查看AI依据”中。

### 4.3 日常使用

首页以决策队列代替传统Dashboard：

- 今日需要批准的推广方案；
- 已生成、等待发布的双语内容；
- 今日发现的高价值客户机会；
- 独立站收到的新询盘；
- AI根据结果给出的下一步建议。

### 4.4 管理员后台

管理员模式负责：

- LLM与多模态Provider、密钥、模型和预算；
- 社媒OAuth、独立站连接器和CRM连接器；
- 数据源、扫描频率、限额和成本；
- Prompt版本、本体、审核规则和证据阈值；
- Job、AIRun、审计、重试和异常；
- Campaign、Brief、平台内容和发布任务的高级维护。

## 6. Growth Director

Growth Director不是聊天窗口，而是现有能力的调度层。

### 6.1 输入

- 已批准企业与产品事实；
- 产品手册和素材；
- 用户一句目标；
- 平台能力和已连接账号；
- 独立站已有产品、博客和内容缺口；
- 历史发布、点击和询盘；
- 公开市场与潜客信号；
- 预算、地区、频率和合规规则。

### 6.2 输出

`GrowthProposal`保存：

- 结构化目标、假设和证据；
- 市场、ICP和内容主题；
- 社媒、独立站和潜客监测计划；
- AI自动生成的底层Campaign/Brief/MonitoringTask草稿；
- 预计调用费用和平台限制；
- 需要人工确认的事实；
- PromptVersion、AIRun和Ontology快照。

批准后才创建或激活底层任务。拒绝和修改成为下一轮决策记忆，但不覆盖历史版本。

## 7. 产品手册到推广内容

### 7.1 摄取

上传文件后创建解析Job：文本提取、图片/OCR、表格识别、产品候选、规格、工艺、应用、标准、优势和不确定项。AI只能创建建议，不直接把推断写成已批准事实。

### 7.2 事实审核

只向用户展示高影响缺口，例如：

- “手册中出现DIN 6，但没有检测报告证据，是否仅作为目标能力而非已具备能力？”
- “未找到正式最小起订量，将使用‘按项目确认’。”

低风险字段采用AI建议；高风险承诺必须人工确认。

### 7.3 生成

每个平台内容包含：

- `source_language`；
- 面向客户的外文版本；
- 一一对应的中文对照；
- 平台、格式、字符限制和媒体要求；
- CTA与独立站目的页；
- 自动生成的UTM和内容ID；
- 使用的企业事实、知识证据和AI审计引用；
- 图片/视频生成请求及素材来源。

## 8. 社媒发布

平台接入优先使用官方OAuth和官方API。用户输入账号名称只能用于识别和引导授权，不能代替平台授权。

每个连接器声明能力快照：

- 可发布格式；
- 可读取指标；
- 可读取评论或公开内容；
- 是否需要应用审核；
- 速率、配额和地域限制；
- 自动、半自动或发布包模式。

批准的内容进入现有发布Job。不可自动发布的平台生成清晰的发布包和操作提示。平台失败不会丢失内容，使用幂等键、有限重试和人工恢复队列。

## 9. 独立站发布

独立站继续使用静态预渲染以保留SEO。

增长系统生成版本化 `WebsitePublicationBundle`：

- slug、语言、标题、摘要和正文；
- 产品、行业、能力和证据引用；
- SEO、canonical、Open Graph和JSON-LD；
- 图片、alt文本和来源；
- CTA、相关产品与询盘预填参数；
- 发布版本、内容ID和校验哈希。

发布连接器把已批准Bundle同步到独立站受控内容目录，执行类型、链接、安全声明和构建验证；验证通过后才触发Cloudflare构建。失败保留上一个公开版本。

不得自动修改正式域名、DNS、邮件和canonical配置。

## 10. 每日获客与证据链

采用Outreach Agent的业务链，不采用高风险采集和自动触达方式：

```text
MonitoringTarget
→ SourceContent
→ SourceSignal
→ SourceEvidence
→ CompanyMatch
→ LeadCandidate
→ LeadInsight
→ Human Review
→ LeadHandoff
```

### 10.1 数据来源顺序

1. 官方API、RSS、公开网站和政府/企业公开数据；
2. 合同许可的数据与企业补全服务；
3. 用户提供的URL、截图、CSV/JSON和批量粘贴；
4. 平台明确允许的账号授权数据。

不把需要登录才能访问的数据默认为可自动采集。

### 10.2 评分

机会分数由可解释维度组成：

- `ICP Fit`：行业、国家、公司类型、产品和能力匹配；
- `Intent`：明确采购、替换、故障、项目、数量或供应商信号；
- `Recency`：信号新鲜度；
- `Authority`：公开身份和可能的决策角色；
- `Evidence Coverage`：结论可追溯程度；
- `Risk`：身份歧义、来源可靠性和合规风险。

没有SourceEvidence的对象不能进入高价值队列。评分只用于排序，不自动联系或拒绝。

### 10.3 用户看到的结果

每个机会卡只展示：

- 公司和国家；
- 可能需要的产品；
- 为什么值得关注；
- 原文、来源链接、时间和截图；
- 可信度与不确定项；
- `交给CRM`、`查看依据`、`忽略`。

## 11. 独立站询盘和归因

所有推广目的地址携带：

- 标准UTM字段；
- 非敏感的 `content_id`、`product_id` 和 `campaign_id`；
- 可验证的短链接或签名上下文。

独立站询盘接口继续先完成现有服务端校验和邮件投递，再通过独立、可重试的签名Webhook回传增长系统。Webhook包含：

- 独立站询盘参考号；
- 询盘时间、语言和来源页；
- 产品、数量、国家及允许保存的联系信息；
- UTM、内容ID、产品ID和平台；
- 附件存在与类型，不在Webhook重复传输大文件；
- 同意和隐私版本；
- 幂等键、时间戳和签名。

Webhook失败不能导致客户看到询盘失败，也不能重复发邮件。增长系统收到后创建InboundEvidence与LeadCandidate，并关联TrackingLink和内容来源。人工确认后才能创建LeadHandoff。

## 12. Analytics Agent

Analytics Agent不只显示点击量，而回答：

- 哪个产品、市场、主题和平台带来了有效访问；
- 哪些内容带来了询盘而不是虚假流量；
- 哪些客户信号最终成为CRM交接；
- 下一轮应该增加、减少或停止什么；
- 建议背后的数据量、置信度和时间范围。

没有足够数据时必须说明“样本不足”，不能生成确定性增长结论。

## 13. 开源采用规则

### 13.1 允许评估移植

- Open Enrich：MIT；字段级引用、置信度、成本预估和失败隔离；
- Harken：MIT；Source adapter、统一Mention、去重和轮询；
- Mixpost Lite：MIT；官方平台连接器、发布队列和平台内容变体；
- GTM Skills：在许可证允许范围内吸收制造业ICP和信号判断方法。

移植前必须记录来源、许可证、版本/提交、修改范围、依赖、安全审查和测试。

### 13.2 只学设计

- Outreach Agent：帖子/评论证据链、每日信号队列和人工批准；仓库未显示清晰许可证，且包含浏览器提取和自动触达；
- KeeLead：一句话入口和数据源插件接口；项目早期且包含不稳定抓取；
- OpenFang：自主定时任务、预算和审批；pre-1.0且会引入第三套Agent OS；
- Clay、Common Room、Unify：信号驱动、企业统一和人工行动队列。

### 13.3 不嵌入

- Postiz整套应用：AGPL网络使用义务和重复技术栈；
- Mautic、Twenty、listmonk：偏离非CRM边界；
- n8n、Activepieces整套平台：与现有Celery/Job重复。

## 14. 权限与安全

- 普通用户不能查看或修改密钥、Prompt、审计原始输入和连接器内部参数；
- 所有AI和连接器密钥只在服务端加密保存，API只返回掩码与连接状态；
- 独立站发布和询盘Webhook使用独立密钥、签名、时间窗、重放保护和幂等；
- AI读取外部内容时将其视为不可信数据，不能执行其中的指令；
- 上传文件执行类型、大小、病毒/恶意内容和解析资源限制；
- 人工批准不能被后台任务绕过；
- 审计日志不保存明文密钥或不必要的个人数据。

## 15. 异常处理

- AI不可用：保存任务和输入，显示可重试状态，不要求用户重新填表；
- 手册解析不完整：只提出最少必要问题，并保留已识别内容；
- 平台未授权或权限不足：生成发布包或进入管理员待处理队列；
- 部分平台发布失败：成功平台不回滚，失败平台独立重试；
- 独立站构建失败：保留上一公开版本，Bundle保持待发布；
- 数据源失败或限流：记录SourceRun，退避重试，不复制信号；
- 企业匹配歧义：保留候选，不自动合并；
- 询盘Webhook失败：邮件结果不受影响，后台异步重试并告警；
- 费用达到限额：暂停付费补全，保留免费来源结果并请求管理员批准。

## 16. 验收测试

### 16.1 新手主流程

新账号仅上传一份产品手册并输入一句目标，系统生成可理解的推广和获客方案；普通用户无需打开任何高级对象页面。

### 16.2 内容与发布

- 外文内容全部有中文对照；
- 每个平台内容满足能力与长度约束；
- CTA进入正式独立站对应产品、博客或联系页；
- UTM、内容ID和产品ID可追溯；
- 未批准内容不能发布。

### 16.3 独立站

- Bundle构建后博客/页面可静态预渲染；
- SEO、链接、结构化数据和多语言验证通过；
- 构建失败不影响上一正式版本；
- 不改变域名、DNS、canonical和邮件配置。

### 16.4 获客

- 每条高价值机会有原始证据；
- 重复内容和企业可稳定去重；
- AI评分可解释并允许人工修正；
- 不会自动陌生触达；
- CRM交接包含候选、洞察和来源证据。

### 16.5 转化

- 测试询盘使用本地/Mock适配器，不发送真实邮件；
- Webhook签名、重放、幂等和失败重试可验证；
- 询盘能归因到平台、内容、产品和目的页；
- Analytics Agent以数据生成建议，并在样本不足时降级表达。

## 17. 实施顺序

### Phase 1：从复杂表单改为AI提案

- 产品手册解析；
- GrowthProposal；
- 前台“上传/目标→批准”；
- 双语内容；
- 普通/管理员导航分离。

### Phase 2：推广到独立站转化

- WebsitePublicationBundle；
- 独立站内容同步和构建验证；
- 自动UTM与目的页；
- 签名询盘Webhook；
- 内容/产品/平台转化归因。

### Phase 3：每日获客信号

- Source adapter接口；
- YouTube、RSS、公开网页及URL/截图/CSV入口；
- 证据、企业匹配、AI评分和每日机会队列；
- CRM人工交接。

### Phase 4：扩展数据与平台

- 官方LinkedIn、Meta、Instagram、TikTok等能力按获批权限接入；
- 付费企业、海关和联系人数据连接器；
- 成本控制、效果评估与连接器淘汰机制；
- AIEO与Analytics Agent持续优化。

每个Phase必须产生可由用户实际操作的端到端结果，不能以新增模型、API或演示页面作为完成标准。

# 账户级效果归因设计

## 目标

在“效果”页增加一个面向工厂老板的账户级获客漏斗，复用现有工作区记录说明每家企业已经走到哪一步、依据是什么、下一步是什么。页面只展示已记录事实；没有人工发送、回复或有效需求事件时，明确显示“尚未发生 / 无数据”，不计算 0% 成功率，也不绘制趋势。

## 范围

- 漏斗顺序：来源/市场 → 候选 → 人工核实 → 资料补全 → 加入跟进 → 草稿生成 → 人工批准 → 人工发送占位 → 回复占位 → 有效需求占位。
- 当前切片只从 `GrowthWorkspace` 已有对象派生，不新增数据库模型、迁移或后端写接口。
- 候选、账户、跟进、草稿、批准必须去重后计数；无法可靠关联的候选只显示独立阶段总量，不虚构账户转化率。
- Demo/Fake 与非 Demo 记录分组展示；来源、市场、渠道筛选只使用现有字段。
- 指标卡优先展示证据覆盖率和草稿批准率；有效账户率在已有账户和验证信号之间计算。积极回复率、需求率因没有对应账户事件而显示“无数据”。数据成本仅汇总已有证据成本，并解释分母。

## 信息结构

1. 效果页顶部保留原有说明，紧接“账户获客漏斗”卡片。
2. 漏斗阶段按钮显示阶段名称、已记录数量或“尚未发生”；点击后筛选下方账户明细。
3. 简单筛选包括数据性质（全部、Demo/Fake、许可/人工记录）、市场、来源和渠道。没有可用值时不显示无意义选项。
4. 账户明细展示：账户名称、市场、数据性质、最远已记录阶段、对应事件时间/证据、建议下一动作。
5. 候选记录没有目标账户 ID 时以“候选公司”明细展示，明确说明尚未进入账户阶段。
6. 人工发送、回复、有效需求阶段没有事件模型，显示占位说明而不是 0、0% 或样例成绩。

## 派生规则

- 候选：`discovery.candidates` 与 `discovery.enrichment_candidates` 按候选 ID 去重。
- 人工核实：候选状态为 `ACCEPTED`。
- 资料补全：已接受候选且存在 `latest_preview`。
- 加入跟进：按 `follow_ups.account_id` 去重。
- 草稿生成：`outreach_drafts.account_id` 与存在 `reactivation.draft` 的账户并集。
- 人工批准：存在已批准重新激活记录，或存在 `crm_handoffs` 的账户并集。
- 有效账户：目标账户存在至少一个已有 `intent_signals`；分母为目标账户数。
- 证据覆盖：有意向证据的目标账户数 / 目标账户数。
- 数据成本：汇总 `field_provenance.source_cost_micros` 与 `intent_signal.evidence_envelope.source_cost_micros`，避免同一证据 ID 的重复累计。
- 人工发送、回复、有效需求：当前工作区没有账户事件，统一为 `null`，UI 显示“尚未发生 / 无数据”。

## 安全与诚实边界

- 不接真实抓取、付费 API、OAuth、真实外发或生产部署。
- 不把 `metric_receipts` 的渠道汇总结果冒充账户回复事件。
- 不把 Demo/Fake 账户与非 Demo 账户合并成一个成功率。
- 不暴露 API、Prompt、内部模型名称等后台概念。

## 验收

- 已批准的重新激活在刷新后出现在“人工批准”阶段和账户证据明细。
- 观察账户显示“补全证据”，不显示已生成或已批准草稿。
- 人工发送、回复、有效需求明确为空，不出现 0% 趋势或虚构记录。
- 点击阶段或筛选项能看到对应账户/候选及事实证据。
- 现有市场 → 候选 → 审核 → 补全 → 跟进 → 草稿闭环 E2E 继续通过。

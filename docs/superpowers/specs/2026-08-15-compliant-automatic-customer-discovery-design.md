# 合规自动客户发现设计

**日期：** 2026-08-15  
**状态：** 已确认进入实现（用户明确要求“自动抓取客户”，并要求普通本地实现持续推进）

## 目标

让工厂老板无需手工录入线索，系统根据已确认的公司与产品事实，定时从许可数据源发现目标公司及可追溯的采购需求信号，并直接进入现有“客户机会”审核队列。

首期不是任意网页爬虫，也不是联系人采集器：不抓取 LinkedIn 登录数据，不绕过验证码，不采集个人邮箱，不自动私信或群发。

## 方案选择

1. 任意网页爬虫：覆盖广，但来源许可、反爬、误报和维护风险高，不采用。
2. 付费商业数据库：联系人覆盖更强，但需要付费账号或密钥，本期只保留适配器边界。
3. 官方采购数据与许可来源适配器：证据稳定、可审计、适合定时增量运行，作为首期方案。

首个真实来源采用欧盟 TED Search API。该接口匿名开放读取已发布采购公告，并提供 CPV、采购方、发布时间、投标截止时间和公告原始链接。齿轮业务使用 CPV `42140000`、`42141000`、`42141100`、`42141200`、`42141300`、`42141400`、`42141500`、`42141600`、`42141700`、`42141800`、`42142000`、`42142100`、`42142200`，避免仅用英文 `gear` 产生多义词误报。

## 用户体验

“客户机会”顶部新增一个极简卡片：

- 主标题“自动发现客户”；
- 显示 AI 推断的产品范围与“每天自动查找”；
- 主按钮“立即查找”；
- 显示上次运行时间、状态、新发现公司数和需求信号数；
- 明确标识“欧盟官方采购数据”或“Demo / Fake”，真实与演示不混用。

后台概念（适配器、游标、API、配额、任务）不暴露给普通用户。新发现结果继续使用现有目标公司、需求信号、原始证据、评分拆分、加入跟进和联系草稿交互。

## 数据与状态

新增 `DiscoveryProfile`（每组织一条）保存：

- 是否启用每日发现；
- 关键词/CPV 快照；
- 每次最大结果数；
- 下次运行时间、上次成功时间；
- 连续失败次数与最近安全错误摘要。

新增不可删除的 `DiscoveryRun` 保存：

- 来源代码、状态和触发方式；
- 查询与能力快照；
- 开始/结束时间；
- 获取、新建、重复、跳过数量；
- 错误代码，不保存密钥或敏感响应。

适配器返回标准化 `SourceItem`。写入时：

- 采购方生成或复用 `TargetAccount`；
- 采购公告生成 `IntentSignal`，`collection_method=OFFICIAL_PUBLIC_API`、`is_demo=false`；
- 公告号与标准化证据生成 SHA-256 内容哈希；
- 同组织同来源公告号幂等；
- 缺采购方、缺 HTTPS 原始链接或字段异常时跳过，不伪造补全。

## 评分

真实公告采用保守、可解释的 `ted-procurement-v1`：

- ICP 匹配：依据 CPV 精度；
- 意向强度：公开采购公告高于普通网页信号；
- 时效：依据发布时间和有效截止日期；
- 角色相关：采购方实体明确，但不等同个人联系人；
- 证据覆盖：公告号、采购方、标题、日期、链接越完整越高；
- 风险扣分：缺截止时间、标题语言回退或采购方身份不完整。

需求信号仍不是已确认询盘；必须人工查看证据后才能加入跟进。

## 调度与安全

- Celery beat 每小时寻找已到期的组织，每个组织默认每天一次；
- 数据库行锁阻止同一配置重叠运行；
- 单次请求超时 15 秒、最多 20 条、响应体有大小上限；
- TED 主机与 HTTPS 路径写死，不接受用户 URL，避免 SSRF；
- HTTP 429/5xx 记录安全错误并指数退避；
- 测试只使用录制 fixture，真实 API 仅做独立只读冒烟验证；
- “立即查找”是读取公开数据并生成内部审核项，不执行任何外联。

## 验收

1. 登录后可在“客户机会”看到自动发现状态并点击“立即查找”。
2. 官方 API 结果能生成非 Demo 目标公司与需求信号，并带可打开的 TED 原始证据链接。
3. 相同公告重复运行不重复创建。
4. 并发、超时、限流、异常字段不会产生假机会，运行记录可解释。
5. 每日任务只运行已启用且到期的配置。
6. 现有手工导入、机会审核、内容与发布流程保持可用。

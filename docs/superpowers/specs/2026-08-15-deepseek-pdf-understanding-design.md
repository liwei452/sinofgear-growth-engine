# DeepSeek PDF 资料理解设计

## 目标

让用户上传的机器可读 PDF 经本地有界文本提取后，由已配置的 DeepSeek 产品 AI 生成带页码和原文证据的候选产品事实。候选事实始终需要人工确认；系统不得把模型输出直接视为已验证事实。

## 边界

- PDF 文件本身不发送给 DeepSeek，只发送最多 100,000 字符的本地提取文本。
- 单文件理解限制保持 20 MiB、30 页、单页解压内容流 10 MiB。
- 图片和扫描 PDF 在没有 OCR/视觉 Provider 时不生成事实，明确提示需要 OCR。
- 真实模式只在 `PRODUCT_AI_PROVIDER=deepseek` 且服务端存在密钥时启用；Fake 模式继续明确标识。
- 不修改独立站，不接真实发布、抓取、OAuth 或生产部署。

## 数据流

1. `pypdf` 在本地提取每页文本并保留页码。
2. 页面文本以不可信证据数据传入 DeepSeek，要求严格 JSON 输出。
3. 返回项只允许产品、规格、工艺、应用、标准、优势，以及精度、认证、材料、产能、交期、价格字段。
4. 服务端逐项校验字段、页码、值长度和原文引用；`source_excerpt` 必须真实出现在对应页文本中，否则丢弃。
5. 通过校验的项写成 `SUGGESTED` 候选事实，保存真实 Provider、模型、页码、原文、置信度和风险等级。
6. 用户逐条批准或驳回；只有 `VERIFIED` 项进入后续 ICP 与内容生成事实输入。

## 安全与失败处理

- 文档中的指令只作为证据文本，不改变系统提示。
- 使用现有固定 HTTPS Endpoint、超时、有限重试、响应大小和 JSON Schema 校验。
- 模型返回部分无效项时保留有效项并显示警告；完全无效时任务失败且可重试。
- 密钥只由服务端 Provider 读取，不进入任务快照、响应、数据库或日志。
- Provider 切换属于新的解析版本；已有 Fake 结果不被覆盖。

## 用户界面

- 操作按钮显示当前解析方式：真实 DeepSeek 或 Fake/离线。
- 结果卡显示 Provider、模型状态、页码、原文、置信度、高风险提示和人工审核动作。
- 扫描件无文字时显示“未提取到可用文字，需要 OCR”，不显示虚构事实。

## 验收

- 机器可读 PDF 可产生真实 DeepSeek 候选事实，且每项证据可回到对应页原文。
- 伪造页码、非原文引用、未知字段和过长值被拒绝。
- Fake 与真实解析任务并存且幂等，刷新后状态保留。
- 高风险事实未经人工批准不能进入事实库。
- 无密钥、图片、扫描 PDF、模型异常均有真实且可恢复的状态。

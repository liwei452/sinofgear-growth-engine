# 证据化客户机会详情设计

日期：2026-08-15

## 目标

把“客户机会”从按单一置信度排序的演示卡片，升级为可解释、可复核、可持续跟进的本地 MVP。普通用户仍只看到“优先跟进、继续观察、已加入跟进”等业务语言，不接触 SourceSignal、Prompt、Campaign 或采集任务等后台对象。

本阶段只使用明确标注 `Demo / Fake` 的本地种子，不访问外部网站、LinkedIn 或付费数据源，不发送邮件或私信。

## 方案选择

采用“后端证据字段 + 前端极简解释”的方案。

- 不采用纯前端分数拆解，因为那会让评分证据变成页面推测。
- 不在本阶段实现完整网页、RSS 或付费数据采集，因为真实许可、配额与来源治理尚未配置。
- 在现有 `IntentSignal` 上补充证据元数据和评分组成，保持现有增长工作区 API 和组织隔离边界。

## 数据设计

`IntentSignal` 增加以下只读证据字段：

- `collection_method`：采集方式代码，首期支持 `DEMO_FIXTURE`、`MANUAL_URL`、`LICENSED_API`、`INBOUND`。
- `content_hash`：证据原文的 SHA-256 十六进制摘要，用于复核和后续去重，不把哈希当作真实性证明。
- `score_breakdown`：固定包含 `icp_fit`、`intent_strength`、`recency`、`role_relevance`、`evidence_coverage`、`risk_penalty`。总分继续使用现有 `confidence` 字段；规则为五项正分之和减去风险扣分。
- `scoring_rule_version`：首期固定为 `opportunity-v1`。
- `uncertainty_notes`：用户仍需人工确认的事项数组。

序列化层输出中文采集方式标签，并校验哈希格式、评分键、分值范围和总分一致性。普通工作区 API 仍为只读聚合；本阶段不新增对外写入证据的端点。

## 页面设计

保持现有左侧机会队列和右侧详情，不改成复杂 CRM：

1. 队列中的数字改称“证据评分”，状态只显示“优先跟进 / 继续观察”。
2. 详情顶部展示总分，并提供六项评分组成；风险以扣分显示。
3. “查看证据”展开后展示原始证据、来源、发现时间、采集方式、规则版本、哈希短码和未确认事项。
4. 来源链接仅允许 `https`，新窗口打开并使用 `noopener noreferrer`。Demo 链接继续指向 `example.invalid`，旁边保持 `Demo / Fake` 标识。
5. 增加轻量“跟进记录”：展示加入跟进时间、最新草稿时间与“从未发送”。不增加销售漏斗、报价、订单或自动触达。
6. 生成草稿后分别显示英文建议和中文解释，不再拼成一段；刷新页面后读取最近一份已保存草稿。

## 错误与安全边界

- 缺少评分组成时页面降级为总分，并明确“评分明细暂缺”，不在前端补造数据。
- 非 HTTPS 来源只显示文本，不生成可点击链接。
- 缺少证据或证据覆盖不足的机会不能显示“优先跟进”。首期阈值为总分至少 80 且证据覆盖至少 15。
- 所有机会继续显示数据标签；Demo 数据不得伪装成真实发现。
- 草稿状态固定为 `NEVER_SENT`，页面没有发送按钮。

## 测试与验收

- 迁移与模型测试覆盖字段默认值、评分结构和 SHA-256 格式。
- API 测试覆盖组织隔离、证据元数据、评分总分一致性和 `NEVER_SENT`。
- 前端测试覆盖高分但证据不足不能进入优先层、评分展开、非 HTTPS 链接、未确认事项、刷新后草稿与跟进时间线。
- 浏览器验收覆盖选择三家公司、查看不同证据、加入跟进、生成草稿、刷新后状态保留。
- 全量后端、前端、类型、lint、构建和迁移漂移检查必须通过。

## 非目标

- 不实现真实来源抓取、RSS 监控、LinkedIn 抓取、联系人邮箱补全或付费数据购买。
- 不实现自动邮件、自动私信、CRM 销售漏斗、工程 RFQ 或报价。
- 不修改或联调 `C:\Users\Administrator\Documents\网站\app`。

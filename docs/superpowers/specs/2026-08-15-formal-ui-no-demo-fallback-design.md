# 正式界面无 Demo Fallback 设计

## 目标

普通用户进入“今天、推广、客户机会、效果、我的公司、内容审核、内容日历”时，只看到真实工作区记录、可执行入口和干净空状态。测试夹具继续保留，但不得在空工作区自动出现。

## 方案选择

采用前端正式视图过滤层：现有接口继续返回组织边界内的数据，各普通页面只渲染非 Demo 记录；硬编码 fallback 全部删除。此方案不删除测试夹具、不新增大型演示租户模型，也不改变现有 Django/Vue 接口边界。

未选择的方案：

- 删除后端 Demo seed：会破坏现有显式演示测试和本地开发证据，不符合“保留 fixture”要求。
- 新增全局演示模式与租户开关：长期更完整，但本轮会引入权限、持久化和组织隔离改造，超出最小清理范围。

## 页面规则

### 今天

- 删除默认 PackTech 等三家公司、固定渠道数字、固定趋势图、固定 AI 可见度分数和虚拟资质。
- 采购机会只显示非 Demo 目标公司且必须有非 Demo 需求信号。
- 无机会时说明当前没有已验证信号，并提供“选择市场”和“导入合法名单”。
- AI 可见度没有真实监测记录时只显示实验模块尚无数据，并提供“补充公司事实”。
- 渠道表现仅来自非 Demo 手工回填；无记录时提供“查看效果/回填结果”。

### 推广

- 删除空工作区固定 TikTok 脚本、分镜、CTA、UTM 和四渠道伪内容卡。
- 只显示非 Demo 内容包；无内容包时提供“创建内容”和“进入审核中心”。
- Demo 连接器不算正式就绪，不得触发正式一键发布；未配置官方连接时显示未连接。

### 客户机会与效果

- 客户机会只显示非 Demo 账户、信号、联系人和结果；空工作区保持已实现的真实入口。
- 效果页只统计非 Demo 回填和非 Demo 账户漏斗。无发送、回复、询盘时继续显示“尚未发生/无数据”。
- 不展示固定成功率或伪造趋势。

### 我的公司、内容审核、内容日历

- 我的公司继续使用真实事实库；无记录时不显示任何资质，并链接资料上传解析。
- 内容审核与内容日历沿用接口空集合，不生成固定文案、排期或通知数字。
- 空状态分别链接“创建内容”和“推广/连接渠道”等已有流程；无效占位按钮删除。

## Demo 隔离

本轮普通 UI 不提供“加载演示数据”按钮。Demo fixture 只由测试显式注入，普通页面的正式选择器统一排除 `is_demo=true`、`mode=DEMO_FAKE` 和等价的 Demo 内容包。未来若增加演示模式，必须使用独立显式开关和隔离数据集。

## 错误与加载状态

- 加载中显示读取状态，不显示 fallback。
- 接口失败显示“暂时无法读取”，保留安全重试或真实入口，不回退 Demo。
- 无数据说明为空原因以及下一步，不显示假数字。

## 验证

- 页面级空工作区测试断言不存在虚拟公司、固定分数、虚拟资质、固定脚本、渠道成绩和伪趋势。
- 显式注入真实记录时原有操作继续可用。
- 显式注入 Demo fixture 时普通正式页面不渲染该记录。
- 跑前端定向、全量、类型、构建和浏览器空工作区检查；本地 3001 保持可访问。

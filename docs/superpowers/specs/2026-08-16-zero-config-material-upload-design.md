# 零配置产品资料上传设计

## 目标

让工厂用户上传 PDF、图片或视频时只需选择文件。系统自动判断素材类型和语言，隐藏非必要设置，并在安全边界内把资料送入现有“解析候选事实 → 人工确认 → 事实库”流程。

## 用户流程

1. 用户在素材库点击“上传资料”。
2. 弹窗默认只显示文件选择器和主按钮“上传并准备产品事实”。
3. 选择文件后，前端依据 MIME 类型与扩展名显示只读摘要，例如“PDF 产品资料”；不要求选择 `DOCUMENT`。
4. 语言默认“自动识别”。标签放入默认收起的“高级设置”，两者都不阻塞上传。
5. 如果组织只有一个可用产品，上传后自动关联该产品并进入事实准备流程。
6. 如果存在多个产品，上传成功后在原弹窗内显示一步式产品选择；用户选择后继续准备事实。
7. 如果没有产品，资料仍安全保存，但明确提示先创建产品，不能生成或写入产品事实。
8. AI 只生成候选事实。价格、交期、精度、认证、材料和产能等高风险事实仍需逐项人工确认。

## 自动判断规则

- 文件类型以浏览器 MIME 与扩展名共同判断，服务端再次校验；两者冲突时服务端拒绝，不信任客户端结果。
- PDF 映射为 `DOCUMENT`，JPEG/PNG/WebP 映射为 `IMAGE`，MP4 映射为 `VIDEO`。
- 语言字段允许空值或 `auto`。解析阶段根据可提取文本判断中文、英文或混合语言；无法判断时保持“未确定”，不影响文件保存。
- 标签完全可选，不因空标签阻止上传。
- 自动关联只在“恰好一个可用产品”时发生；多个产品不得由 AI 猜测归属。

## 错误与安全边界

- 用户界面只显示中文可行动提示，不回显解析器异常、内部路径、堆栈或响应原文。
- 截断或结构异常 PDF 显示：“PDF 文件不完整或结构异常，请重新导出后上传。”
- 无文本扫描 PDF 显示：“这是扫描版 PDF，当前需要 OCR 后才能整理事实。”文件可保留，不能伪装成已理解。
- 不支持的格式、大小超限、页数超限分别给出明确提示。
- 上传成功但事实准备失败时保留素材，提供“重新准备”按钮，不要求重新上传。
- 真实 DeepSeek 模式仍需本次主动同意发送裁剪后的有限文本；PDF 二进制本身不发送。

## 界面结构

上传弹窗首屏仅包含：

- 文件选择器；
- 选择后的文件名与自动识别结果；
- 默认收起的“高级设置”（语言覆盖、可选标签）；
- “取消”和“上传并准备产品事实”。

多产品组织在上传成功后切换为产品选择步骤，不新开第二个后台页面。素材卡片保留当前事实状态、来源证据、重试和人工确认入口。

## 后端与兼容性

- 复用现有素材上传、产品关联、资料理解任务和候选事实模型，不新增平行上传系统。
- 上传接口接受省略的素材类型和语言，由服务端推断并保存规范化值。
- 提供一个编排操作完成“保存素材 → 唯一产品自动关联 → 创建事实准备任务”；任一步失败都返回稳定状态，并保证素材不会重复创建。
- 保持现有显式字段兼容，旧客户端仍可传入类型、语言和标签。
- 重复提交使用现有文件与请求幂等边界，不能创建重复事实任务。

## 验收

- PDF、图片和视频均只选文件即可上传，类型自动正确。
- 不填写语言和标签也能完成上传。
- 一个产品时自动关联并准备；多个产品时只增加一次产品选择；零产品时给出真实下一步。
- 英文底层异常不会出现在普通用户界面。
- 异常 PDF、扫描 PDF、超限文件和类型伪装均被安全处理。
- 上传、关联、准备、重试、人工确认刷新后保留，且组织隔离不回退。
- 运行前后端定向测试、全量测试、类型检查、构建和浏览器闭环。

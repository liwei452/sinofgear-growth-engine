# SinofGear Agent 工作台重组设计

## 1. 目标

将当前以菜单和表单为中心的后台重组为一套能清楚表达“AI 发现机会、提出建议、调用工具、等待人工批准、执行并复盘”的增长工作台。

本次改造必须解决四个已确认问题：

1. Agent 能力存在于代码中，但用户无法理解其角色、模型、过程和产出。
2. DeepSeek 适配器存在，但没有管理员可操作的模型配置入口。
3. 效果页同时承担经营查看、数据录入和技术审计，信息过载。
4. 社媒连接和发布能力仍在代码中，但主要入口被导航隐藏。

真实邮箱接入不属于本次范围；所有邮件相关能力继续保持未激活状态。

## 2. 设计原则

- 任务优先：首先告诉用户今天要处理什么，而不是展示系统拥有哪些表。
- Agent 可解释：区分 AI Agent、AI 内容生成和固定自动化流程，不能混用名称。
- 人工控制：任何对外发布、客户触达和高风险写入仍需人工批准。
- 少而清楚：首屏只展示关键状态、核心数字和下一步动作，详情按需展开。
- 真实状态：未配置、无数据、等待平台审核必须明确显示，不使用虚构成功数据。
- 明亮专业感：使用高明度科技蓝、浅蓝白和少量暖色提示，不使用沉重蓝灰、大面积暗色或装饰性图标堆叠。

## 3. 视觉方向

视觉参考采用用户提供的后台工作台图片，但只借鉴其布局逻辑：

- 轻量左侧导航，图标与文字成组，当前项用低饱和品牌色强调。
- 顶部栏只保留页面上下文、全局搜索入口、待审批提醒和用户菜单。
- 主内容区采用 12 栏桌面栅格，主要工作区约占 8 栏，辅助信息区约占 4 栏。
- 卡片之间以留白区分，边框弱化；使用轻柔浅蓝阴影建立层级，只对可操作或需要注意的区域使用更强状态色。
- 数据卡片采用图形、趋势和短标签，不堆砌说明段落。
- 右侧辅助栏只放等待审批、模型状态、渠道异常和最近任务。
- 页面正文默认最大宽度 1440px；桌面内容密度适中，移动端改为单列。

颜色改为参考图所体现的明亮 AI SaaS 体系，不继续使用当前偏沉的工业蓝灰：

- 主色：明亮科技蓝，建议基准 `#1687FF`；强调态可使用 `#0875EB`。
- 浅主色：`#EAF4FF`，用于选中项、图标底和弱提示。
- 页面背景：带轻微蓝相的近白色 `#F5F9FE`。
- 卡片背景：纯白 `#FFFFFF`。
- 主文字：清晰深蓝黑 `#102A56`，不用纯黑。
- 次级文字：`#66809F`。
- 正向：清透绿色 `#28B887`。
- 待处理：明亮橙色 `#FFAA3D`。
- 风险：清晰但克制的红色 `#EF5B5B`。

允许在核心数据卡和主操作按钮中使用非常轻的蓝色渐变，但禁止满页渐变、荧光发光和大面积深色背景。整体观感必须明亮、干净、轻盈，接近参考图下半部分的医疗数据工作台，而不是传统工业管理软件。

图标继续使用现有统一图标组件，不使用 Emoji 充当正式导航图标。

## 4. 信息架构

### 4.1 主导航

```text
今天

客户增长
├─ 客户机会
└─ 地图获客

AI Agent
└─ Agent 工作台

内容与社媒
├─ 内容创作
├─ 内容审核
├─ 社媒运营
├─ 发布日历
└─ 平台账户

效果
└─ 经营效果

公司资产
├─ 产品库
├─ 知识库
├─ 素材库
└─ 公司资料

设置
```

`/promotion` 保留现有路由兼容性，但页面名称和入口统一改为“社媒运营”。

### 4.2 今天工作台

桌面端采用“主区 + 右侧辅助栏”。

主区依次显示：

1. 今日问候、系统日期和一句业务摘要。
2. 四个核心状态：新机会、等待审批、待发布、收到询盘。
3. 今日优先任务，最多五项，每项只有原因、建议动作和主按钮。
4. 最近机会，最多五家公司。
5. 最近七天简化趋势。

右侧辅助栏显示：

1. Agent 与模型状态。
2. 等待人工审批的前三项。
3. 社媒渠道异常或未连接状态。
4. 最近完成的三个 Agent 任务。

空数据时显示明确的第一步，不展示零值仪表盘墙。

## 5. Agent 工作台

### 5.1 能力分组

首版展示四个岗位：

- 获客 Agent：发现企业、补全公开信息、评估匹配度、准备跟进建议。
- 内容 Agent：提出选题、生成内容 Brief、调用内容生成任务、准备平台版本。
- 社媒 Agent：分析已批准内容、提出排期建议、准备发布、复盘已有数据。
- 客户激活 Agent：识别沉睡账户、整理已有证据、生成重新联系建议。

每张 Agent 卡必须标明能力类型：

- `AI Agent`：大模型可以根据目标和工具描述选择下一步。
- `AI 生成任务`：大模型生成内容，但执行路径固定。
- `自动化流程`：不调用大模型规划，只按确定规则执行。

### 5.2 Agent 任务详情

普通用户看到时间线：

```text
读取资料 → AI 分析 → 提出动作 → 等待批准 → 执行 → 结果
```

每一步显示：

- 做了什么；
- 使用了哪些已确认事实；
- 为什么建议下一步；
- 是否需要人工批准；
- 执行结果和恢复建议。

原始工具名称、参数 JSON 和错误代码放入“技术记录”折叠区。

### 5.3 大模型规划边界

配置真实 DeepSeek 后：

- 获客 Agent 使用受约束的 LLM Planner。
- 内容策略和社媒策略可使用受约束的 LLM Planner。
- 内容生成继续使用现有 JSON Schema 约束的 DeepSeek 生成链路。
- 平台变体、数据库写入和发布动作继续由确定性工具完成。

Fake 模式继续使用确定性 Planner，并在界面标记“离线演示”，不能显示成真实 Agent 决策。

所有 Planner 都必须受工具白名单、最大步骤数、JSON Schema、组织隔离和人工审批约束。

## 6. AI 模型配置

### 6.1 管理员页面

设置中心新增 `/settings/ai-model`，仅管理员可访问。

首版支持：

- Provider：DeepSeek。
- 模型：`deepseek-chat`、`deepseek-reasoner`。
- API Key：仅输入，不回显。
- 测试连接。
- 启用和停用真实请求。
- 删除已保存密钥。
- 每日美元预算和超额停止。
- 最近连接状态、最近成功调用时间、Token 和估算费用摘要。

其他 Provider 不在本次实现范围内，页面不放置不可用的占位选项。

### 6.2 安全

- API Key 不进入前端缓存、日志、审计输出或普通 API 响应。
- API Key 使用服务端主密钥加密后保存，模式复用现有 OAuth 加密凭据边界。
- GET 只返回 `configured`、Provider、模型、状态和安全统计。
- 测试连接由服务端执行，使用固定官方 DeepSeek 地址，不允许用户输入任意 Base URL。
- 写入、测试、停用和删除操作要求管理员权限、CSRF 和组织隔离。
- 密钥更新后旧密文不可再使用；删除操作保留不含秘密的审计记录。

### 6.3 运行时解析

每次 AI 任务从当前组织的有效配置解析 Provider 和模型。组织没有有效配置时，保持当前明确的 Fake/配置缺失状态，不静默调用其他组织或全局密钥。

环境变量配置仅作为开发和迁移兼容路径；组织级后台配置优先。

## 7. 社媒运营

`/promotion` 页面重组并更名为“社媒运营”。内容工作区导航包含五项：创建、审核、社媒运营、日历、账户。

页面顺序：

1. 五渠道连接概览：Facebook、Instagram、LinkedIn、TikTok、YouTube。
2. 今日待发布内容。
3. 等待审核内容。
4. 排期与最近任务。
5. 最近发布结果。
6. 手工发布包入口。

每个渠道卡只显示：连接状态、可用能力、阻塞原因和一个主操作。

OAuth 未启用时显示“需要管理员完成平台配置”；等待平台审核时显示“账号可连接，公开发布仍未激活”；不得隐藏整个平台。

平台账户页继续负责账户和凭据生命周期，社媒运营页负责日常内容和发布工作。

## 8. 经营效果

经营效果页首屏只显示：

- 有效客户数；
- 已批准内容数；
- 已发布内容数；
- 有效询盘数；
- 最近 30 天趋势；
- 渠道效果对比；
- 一条可执行的 AI 建议。

没有真实数据时显示“无数据”及建立数据链路的入口，不补零、不推算。

以下内容移出首屏：

- 九阶段账户漏斗：移到客户机会的“转化漏斗”标签。
- 手工渠道回填：移到经营效果的二级“数据录入”抽屉或独立管理区。
- 追踪链接和短链接：保留在管理员高级数据页。
- 证据详情和计算口径：通过“查看依据”抽屉展示。

## 9. 组件边界

新增或重组以下前端单元：

- `AgentWorkspacePage`：Agent 岗位、运行状态和任务列表。
- `AgentCapabilityCard`：单个 Agent 能力、类型和主操作。
- `AgentRunTimeline`：面向业务用户的执行时间线。
- `ModelStatusCard`：模型连接、预算和最近调用摘要。
- `AIModelSettingsPage`：管理员模型配置。
- `SocialOperationsPage`：社媒连接、待发布和排期概览。
- `EffectivenessOverview`：经营效果首屏。
- `DashboardSideRail`：今天页的审批、模型和渠道异常。

现有大文件应按上述责任拆分，但不进行与本目标无关的全局重构。

## 10. 错误与空状态

- 模型未配置：显示配置入口，不提供会失败的启动按钮。
- API Key 无效：测试连接失败，保留旧的有效配置，返回安全错误。
- 预算已用尽：停止新 AI 请求，保留固定规则和人工操作能力。
- 社媒 Provider 未配置：显示管理员操作说明，不显示输入平台密码的表单。
- 平台审核未完成：允许准备内容和手工发布包，不宣称自动发布可用。
- Agent 失败：显示失败步骤、业务化原因和重试/返回人工处理动作。
- 数据为空：显示一个明确的第一步，不显示大面积空表格和无意义零值。

## 11. 响应式与可访问性

- 桌面端主区与右侧栏为 8:4；低于 1100px 改为单列，辅助栏移动到主区下方。
- 低于 860px 使用现有抽屉式侧栏。
- 所有状态不能只靠颜色表达。
- 所有图标按钮必须有可读标签。
- 时间线、图表和卡片提供语义化标题与文本替代。
- 键盘可访问审批、配置、连接和发布动作。

## 12. 测试与验收

### 12.1 前端

- 主导航能发现 Agent 工作台和社媒运营。
- 普通用户和管理员看到符合权限的入口。
- Agent 卡正确区分三种能力类型。
- 技术 JSON 默认折叠，业务时间线默认可见。
- 模型未配置、已配置、测试失败、预算超限状态均有可用界面。
- 效果首屏不再渲染账户长列表和手工回填表单。
- 五个社媒渠道始终可见，并显示真实连接状态。
- 响应式布局和键盘导航通过组件测试与关键 E2E。

### 12.2 后端

- 组织级 AI 配置严格隔离。
- 密钥加密保存，任何序列化、异常和日志都不含明文。
- 非管理员无法写入、测试或删除配置。
- 测试连接只访问固定 DeepSeek 官方地址。
- 运行时优先使用组织配置，停用或删除后立即停止真实请求。
- 预算预留和结算继续防止并发超额。
- LLM Planner 只能选择白名单工具，非法计划安全失败。
- 社媒连接器和既有发布安全门槛不得回归。

### 12.3 完成标准

- 用户从侧栏最多一次点击进入 Agent 工作台、社媒运营和经营效果。
- 管理员可在界面完成 DeepSeek 配置和连接测试，不接触服务器环境文件。
- 首页能在 10 秒内回答“今天最该做什么、Agent 是否正常、哪些事情等我批准”。
- 效果页首屏在常规桌面高度内呈现核心结果，不要求连续滚动查看表单和证据。
- Fake、未配置、平台未审核和无数据状态均不被包装成成功。

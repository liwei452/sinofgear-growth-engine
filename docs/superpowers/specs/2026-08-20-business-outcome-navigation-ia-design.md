# SinoFGear 业务结果导向导航与信息架构设计

日期：2026-08-20  
状态：已完成产品方向确认，待实施计划  
模式：Operate（操作型产品）

## 1. 目标与用户

SinoFGear 面向初创外贸工厂的负责人和外贸经理。用户具有商业经验，但不应被要求理解 CRM、Agent、Provider、任务状态机或发布连接器等内部技术概念。

本次调整把产品从“按系统模块导航”改为“按业务结果导航”。用户进入系统后，应在五秒内知道：

- 现在正在发生什么；
- 哪个机会最值得处理；
- 什么因素阻塞了推进；
- 有什么可靠证据；
- 下一项有效动作是什么。

成功标准：用户能够按照“今日判断 → 启动推广 → 审核客户 → 准备和发布内容 → 查看效果”的自然路径完成工作，而无需先理解“增长任务”等内部对象。

## 2. 设计原则

1. 业务结果优先，系统对象退居后台。
2. 一个区域只突出一个主行动。
3. 证据、来源和观察时间必须伴随客户与建议出现。
4. 缺失数据要说明缺少什么以及如何补齐，不用装饰性零值填充。
5. 真实外发、内容发布和客户联系继续保留人工审核。
6. 一级导航控制在五项；公司、帮助、设置和账户位于侧栏底部。
7. 中文业务语言优先，必要的英文平台名称保持官方写法。

## 3. 一级导航

主导航固定为五个业务入口：

1. **今日**：经营驾驶舱和统一待办。
2. **开始推广**：持续推进市场、客户发现、内容和渠道准备。
3. **客户机会**：审核、补全和跟进潜在客户。
4. **内容与发布**：准备、审核、排期、提交和处理发布结果。
5. **效果**：查看从客户发现到询盘和成交的转化路径。

侧栏底部保留低频入口：

- 我的公司；
- 帮助；
- 设置；
- 用户账户。

“增长任务”继续作为内部数据与流程容器存在，但不再作为用户必须理解的一级导航。

## 4. 页面职责

### 4.1 今日

今日是经营驾驶舱，不是统计报表，也不是所有功能的快捷入口。

首屏依次回答：

1. 今日最重要机会；
2. 当前关键阻塞；
3. 最新有效证据；
4. 当前唯一主行动。

首屏下方展示统一待办队列，待办可来自客户审核、资料补全、内容审核、发布异常和客户跟进。每项待办必须显示来源、原因、风险和完成后的下一步。

空状态不得制造机会或数据；应说明系统等待什么输入以及用户可以执行的一个动作。

### 4.2 开始推广

开始推广是持续工作台，不是每次重新开始的向导。

首次进入时，以简化步骤呈现：

1. 确认公司和产品资料；
2. 选择目标市场；
3. 确认理想客户画像；
4. 选择合法客户来源；
5. 准备推广内容；
6. 连接渠道或选择人工发布方式；
7. 人工确认启动。

后续进入时直接恢复当前进度，显示：

- 当前市场和理想客户；
- 已完成步骤；
- 当前阻塞步骤及原因；
- 最近发现的客户；
- 待准备或待审核内容；
- 下一项有效动作。

完成步骤折叠成摘要，只展开当前步骤。发布成本、Provider 限制和账号未连接状态仅在相关步骤出现。

### 4.3 客户机会

桌面端采用列表与详情并列的主从结构；移动端采用独立列表页和详情页，并通过 URL 保留筛选、排序、选择与返回位置。

列表显示：

- 公司和国家；
- 行业及规模（有可靠数据时）；
- 需求或意向摘要；
- 来源及观察时间；
- 证据状态；
- 当前跟进阶段。

详情显示：

- 推荐原因和评分解释；
- 原始证据与来源链接；
- 公司画像；
- 公开联系路径；
- 联系人和资料补全状态；
- 跟进时间线；
- 当前允许执行的动作。

Target Account、Contact、Intent Signal 和 Inbound Lead 保持独立对象，不在界面或数据含义上混为“客户”。

### 4.4 内容与发布

内容按工作状态组织，而不是先按社媒平台拆分：

1. 待准备；
2. AI 草稿；
3. 待人工审核；
4. 已排期；
5. 已提交、等待平台确认；
6. 已发布；
7. 失败、需要处理。

进入单条内容后，再展示 LinkedIn、Facebook、Instagram、TikTok 等平台版本、证据、素材、发布方式和结果。

人工发布包、平台官方接口和 Buffer 发布必须使用清晰不同的状态与文案。任何真实外发继续要求人工确认；未知提交结果不得呈现为失败后可直接重试。

### 4.5 效果

效果页首先展示完整转化路径：

发现公司 → 人工确认 → 找到联系路径 → 创建跟进 → 获得回复 → 形成询盘 → 成交。

第二层才展示：

- 渠道表现；
- 内容表现；
- 市场表现；
- 客户来源；
- 平台发布结果。

所有图表都需要文字或表格替代。折线图至少需要四个真实时间点；缺少数据时说明缺少的记录以及前往哪个任务补齐。

### 4.6 我的公司

我的公司是业务事实和准备度的来源页，不是技术设置页。

包含：

- 公司资料和待确认事实；
- 产品及已验证产品事实；
- 素材、文档和 AI 理解状态；
- 内容准备度及缺口；
- 社媒账号准备度摘要。

准备度必须来自真实记录和明确前置条件，不显示任意百分比。

### 4.7 设置

设置只管理系统行为，不承载日常业务流程。

默认显示：

1. 当前阻塞配置；
2. AI 模型与密钥；
3. 推广与发布连接；
4. 通知与 CRM。

团队权限、安全和技术管理折叠到高级设置，并继续受现有角色与权限控制。

产品库、知识库和素材库从“我的公司”的具体上下文进入，不占一级导航。

## 5. 路由策略

保留现有 URL、权限、API 和数据模型，只调整入口、页面组合和展示层职责。

| 新入口 | 路由策略 | 现有承载能力 |
|---|---|---|
| 今日 | `/` | Dashboard、TodayWorkInbox、审批队列 |
| 开始推广 | `/promotion`，取消重定向 | Promotion 与 Mission 相关组件 |
| 客户机会 | `/opportunities`，取消重定向 | Opportunities、目标公司、联系人和信号组件 |
| 内容与发布 | `/content-factory` 为主入口；审核和日历保留二级路由 | Content、Review、Publishing Calendar |
| 效果 | `/analytics` 为主入口，`/attribution` 保留深层入口 | Attribution 与 Results 组件 |
| 我的公司 | `/company` | Company、Products、Assets、Knowledge |
| 设置 | `/settings` | AI、Platform Accounts、CRM、权限与高级入口 |

旧 `/missions` 保留兼容访问和内部深层链接，但不再占据一级导航。已有收藏、浏览器历史和外部链接不得失效。

## 6. 状态与反馈

每个主页面必须覆盖：

- 首次使用；
- 正常有数据；
- 无数据；
- 加载；
- 局部失败；
- 权限不足；
- 配置阻塞；
- 操作成功；
- 操作结果未知；
- 大量数据与长文本；
- 刷新和返回后的状态恢复。

原始枚举必须转成中文业务结果。例如：

- `RUNNING` → “正在获客”；
- `WAITING_APPROVAL` → “等待人工审核”；
- `SUBMISSION_UNKNOWN` → “已提交，等待平台确认”；
- `CONFIGURATION_REQUIRED` → “缺少渠道连接，暂不能发布”。

颜色不能成为唯一状态信号；状态同时使用文字和图标。

## 7. 响应式与可访问性

- 桌面端保留固定侧栏和紧凑顶栏。
- 移动端侧栏使用可关闭抽屉，并保留现有焦点管理、Esc 行为和焦点恢复。
- 客户机会的列表与详情在移动端拆成独立 URL 状态。
- 主要触控目标不小于 44 × 44px。
- 页面只保留一个 `main` landmark。
- 异步动作必须通过 live region 通知成功、失败或未知结果。
- 筛选、排序和选中状态应进入 URL 或使用已有持久化方式，刷新后不得丢失。

## 8. 权限与角色

现有权限是唯一访问依据，不因新导航而放宽。

- 无权访问整个业务入口时，隐藏入口。
- 仅部分功能无权限时，保留页面并隐藏或禁用相关动作，同时解释原因。
- 管理员配置入口不进入普通运营用户的主工作流。
- 只读角色默认进入效果视图，并可查看但不能执行修改或外发动作。

## 9. 实施边界

本次信息架构允许修改：

- Vue 路由和导航配置；
- 页面组合与展示结构；
- 展示层状态归类和业务文案；
- 现有组件复用及新的纯展示组件；
- UI、无障碍和浏览器测试。

本次信息架构不允许修改：

- 后端模型、API、权限和迁移；
- AI 行为和提示词；
- OAuth、发布、获客、CRM 和归因逻辑；
- 独立站；
- 真实账号、真实发布、真实联系或付费服务；
- 虚构客户、机会、指标、准备度或通知。

## 10. 分阶段交付

实施拆成可独立验收的阶段：

1. 路由、五项导航和共享页面标题；
2. 今日经营驾驶舱；
3. 开始推广持续工作台；
4. 客户机会主从工作区；
5. 内容与发布状态工作区；
6. 效果转化路径；
7. 我的公司与设置重新分工；
8. 响应式、无障碍、历史路由兼容与全量回归。

每一阶段使用真实 API 数据和诚实空状态，不进行一次性大型 CSS 重写。

## 11. 验收标准

- 一级导航只有五项，底部入口与用户菜单层级明确。
- 用户无需理解“增长任务”即可完成主要流程。
- `/promotion` 和 `/opportunities` 不再重定向到 `/missions`。
- 今日首屏能回答机会、阻塞、证据和下一步。
- 内容与发布按工作状态组织，平台差异进入详情。
- 效果页首先展示完整真实转化链路。
- 我的公司承载业务事实，设置承载系统行为。
- 所有权限、安全审核和发布保护保持不变。
- 桌面和移动端主流程可完成，刷新和返回保留必要状态。
- 单元测试、API 契约、类型检查、构建和关键浏览器流程全部通过。
